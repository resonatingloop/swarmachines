# report evidence / carry the record into the write-up

status: accepted

accepted by colette in the coding conversation on 2026-11-07; implementation authorized.

owner: colette · proposed implementer: asterion · 2026-11-07

## owner view

- change: select comparison turns and download a small, inspectable evidence packet for the report authors.
- before: the paired viewer exposes differences, but transferring them into the write-up requires manual copying without a durable source reference.
- after: preview the exact export, then download structured json and a readable markdown companion with matching counts, source hashes and caveats.
- authority: this is an accepted export contract. it neither writes the research report nor promotes selected records into causal conclusions.

## context

build on the [paired comparison contract](004-paired-episode-comparison.md) and [comparison model](../viewer/comparison.js). preserve the [freight evidence distinction](003-freight-replay-handoff.md): a reproducible scaffold can supply compatibility evidence without proving world-backed outcomes. the exporter reuses the viewer's computations rather than creating a second interpretation of the log.

## scope

in:
- select up to 32 recorded turns from the loaded pair; add/remove the current turn and clear the selection.
- preview and download a versioned json evidence packet and a readable markdown projection.
- byte-level source hashes, slot-scoped record references, selected-turn counts/deltas, configuration comparison and explicit limitations.
- offline generation and explicit user-initiated downloads only.

out:
- raw message bodies, observation payloads, entire logs, screenshots, auto-written conclusions, statistical tests or morphology scores.
- report-template integration, publishing, clipboard automation, provider calls, network access or browser persistence.
- manual annotations, editing source records, or certifying the pair as a controlled experiment.

## owner decisions

### derived evidence with source pointers

- recommendation: export derived counts and precise record references, leaving raw payloads in the original files.
- alternative: embed every supporting payload; that increases disclosure and packet size without being necessary for this first report bridge.
- consequence: reviewers need the original files to inspect raw evidence. the packet must say that it is not self-contained proof and include hashes so those files can be identified.

### json plus readable markdown

- recommendation: one canonical packet object, two explicit download buttons. json preserves types; markdown makes the same evidence convenient to read and quote accurately.
- alternative: markdown only, which loses machine-checkable distinctions such as unavailable versus zero.
- consequence: both representations share a packet id, selections, counts and caveats; they must never be generated by separate calculation paths.

## packet contract

schema identifier: `swarmachines.evidence-packet.v1`. exporter version: an explicit version string owned with the implementation. changing output semantics requires a version change.

packet fields:

- `schema_version`, `exporter_version`, `packet_id`, and `scope: selected-turn-record-comparison`.
- `sources.left` and `sources.right`: exact imported-byte sha256, byte length, run_id, recorded turn range, event count, and run.end-present flag. identify sources by slot and digest; omit local filenames and paths.
- `selection`: sorted unique selected turns and alignment `last-record-at-or-before-turn`.
- `configuration`: the existing field comparison statuses and logged values. preserve missing/conflicting versus explicit null using tagged values; include references to every configuration record. label this file-level context, independent of selected turns.
- `turns`: each turn's left/right availability status, per-type event counts, right-minus-left deltas, and contributing record references. unavailable counts/deltas are null, never zero. each reference contains slot, run_id, seq, turn and type.
- `observations`: latest recorded observation references at each selected cutoff, grouped per slot with agent id, original turn and carried-forward flag; no observation payloads.
- `disturbances`: references to disturbance records through each selected cutoff; no free-form detail payloads. do not imply their effects have been established.
- `limitations`: fixed caveats below plus derived missing-config, conflicting-config, missing-turn, unequal-horizon and absent-run.end warnings where applicable.

message/action ids are not cross-run join keys. repeated supporting references across selected turns are permissible; each count's contributors must remain unambiguous. unknown event types remain in the source log; disclose that the exported count vocabulary covers only the comparison model's named types.

## provenance and deterministic construction

hash the original file bytes before decoding; do not hash reserialized json or normalized line endings. two byte-distinct files may have equivalent records but different hashes. use local browser cryptography; if unavailable or hashing fails, comparison remains usable but export stays disabled with an explanation. never substitute run_id for a content digest.

construct a deterministic packet from the loaded bytes, selected turns and exporter version. no current timestamp, filename or filesystem path enters its identity. compute packet_id as sha256 of the deterministic UTF-8 serialization of all packet fields except packet_id, using the exporter-defined stable key order. insert the id afterward. document the exact serialization so it can be independently recomputed. the markdown heading includes the same packet_id.

hashes identify bytes; they do not verify the producer, correctness or experimental design. do not infer world-backed status from filenames, run ids, config equality, or the presence of freight-shaped fields. outcome values from run.end are intentionally excluded from this slice.

## selection, preview and lifecycle

both slots must be loaded and hashed, with at least one selected turn. allow only turns in the current union and cap selection at 32. replacement of either source clears all selections and any prepared packet only after successful import; failed replacement preserves the prior pair, selection and prepared packet. reset/reload clears everything. pending imports disable preparation and downloads until settled; stale asynchronous hash/prepare completions cannot resurrect old state.

“prepare evidence” freezes a snapshot of sources and selections into an immutable packet and displays its exact json and markdown in text-only, scrollable preview panes. preview includes byte sizes and a concise inclusion note: logged config values and identifiers are included; raw payloads and filenames are excluded. selecting/removing a turn invalidates the prepared packet. moving the inspection cursor alone does not alter the selected turn set or prepared packet.

provide separate “download json” and “download markdown” buttons, enabled only for the current prepared snapshot. each explicit click downloads one fixed safe filename, `swarmachines-evidence.json` or `swarmachines-evidence.md`; never derive filenames from imported text. use local blobs and revoke object urls after use or reset. a browser download request is not proof that the user saved a file.

bound each output at 2 mib of UTF-8. if either exceeds the limit, refuse preparation with “select fewer turns”; never silently truncate references, warnings or payload fields. selected source files remain untouched. show progress/error state accessibly and keep the ordinary viewer usable if export fails.

## readable projection and text boundary

markdown contains source digests, selection/alignment, a configuration summary, per-turn count tables, supporting references, observation ages, disturbance references and all caveats. show unavailable cells as “unavailable.” identify columns as event counts and delta as right minus left.

imported values remain inert text in browser previews. escape markdown syntax and html metacharacters in imported strings; preserve newlines/control characters as explicit escaped text so they cannot break tables, introduce links, or create raw html when the markdown is rendered. generated headings/tables are authored syntax, not source-derived markup. json uses normal JSON escaping and preserves exact identifiers.

configuration values can contain arbitrary producer-supplied content. the export is intentionally local and previewable; do not describe it as anonymized or automatically safe to publish. no raw source text is sent to discord, a report service or a provider.

## fixed limitations

- paired files are not a certified matched experiment; equal logged settings do not establish equal worlds, policies or generation controls.
- counts describe records, not unique messages, successful decisions, delivered freight or causal effects.
- selection may omit relevant turns; selected-turn summaries are not whole-run estimates.
- carried-forward observations retain their recorded age; missing records and missing turns are not evidence of no activity.
- source hashes establish byte identity only. original source files are required for raw evidence inspection.
- configuration is file-level context; cursor-scoped evidence remains bounded by each selected turn.
- no outcome or world-backed claim is established by this export.

## implementation order

1. define deterministic packet construction and pure markdown projection using the existing comparison model; test provenance, null/zero distinctions, contributors and exclusions.
2. retain exact imported-byte digests in slot state without changing comparison semantics; gate export on both sources and protect asynchronous state transitions.
3. add selection, prepare/preview and explicit downloads; bound output and safely dispose blob urls.
4. exercise downloaded artifacts in the browser, document the packet contract and hand off through the standing commit/pr/caduceus procedure.

likely changes: a pure evidence module and tests, paired viewer controls/controller, focused browser export checks and viewer notes. no runner or report-authoring files need changes.

## done when

- identical bytes, selections and exporter version produce identical packet content/id; changed source bytes change provenance even when parsed records are equivalent.
- every exported count equals its referenced contributors and the viewer's count; unavailable stays null in json and explicit in markdown.
- shared ids remain slot-scoped; carried observations include original turn and age status; future evidence is excluded from selected-turn data.
- json and markdown agree on sources, selected turns, counts, configuration status, packet id and limitations.
- raw messages/observations, filenames, paths and outcome totals are absent from the defined export fields; imported markdown/html-like identifiers stay inert.
- source replacement, selection changes, reset, failed imports and late hashes obey the prepared-snapshot rules.
- output-size refusal is explicit and never truncates evidence; each download is a user action with a fixed filename and valid contents.
- original viewer/comparison tests remain green; export operates offline with no browser storage, network or provider calls and usable keyboard/narrow layout.

## validation

extend `node --test viewer/*.test.cjs`; retain both browser suites and add export-specific browser checks that read the downloaded files. recompute hashes/packet ids independently in tests; compare projected markdown values with canonical packet data. cover missing turns, duplicate ids, config conflicts, oversized output, escaped values, both source replacements and async races. run documentation and atlas freshness checks before handoff.

## risks and unknowns

- selective exports can encourage overclaiming; the packet carries selections and caveats but cannot police report interpretation.
- source files are required for raw evidence review. distributing them is a separate owner decision.
- local cryptography/download support must be exercised in the target browser; fallback is continued comparison with export disabled, not weakened provenance.
- implementation proof is recorded in viewer notes; export-boundary independent review remains a release gate.

## open questions

- none; the derived-only packet, explicit downloads and local provenance rules were accepted.
